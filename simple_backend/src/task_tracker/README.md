## Хранение состояния и минусы in-memory подхода

**Хранение состояния** — это сохранение данных приложения между запросами и перезапусками.  
В первом варианте проекта задачи хранились в оперативной памяти Python-процесса (`dict[int, Task]`).

### Минусы in-memory хранения
1. **Потеря данных при перезапуске** – рестарт сервера/краш = список задач обнуляется.
2. **Нет шаринга между процессами/инстансами** – каждый воркер держит свой список; в проде с несколькими инстансами данные расходятся.
3. **Невозможно горизонтально масштабировать** – без внешнего общего хранилища инстансы не согласованы.
4. **Нельзя сделать бэкапы и восстановление** – память не предназначена для долговременного хранения.
5. **Трудно гарантировать целостность** – при одновременных запросах возможны гонки (race conditions) и потеря обновлений.
6. **Утечки памяти** – долгоживущий процесс с растущим списком может съесть RAM.
7. **Нет истории/аудита** – нельзя восстановить кто/когда что изменил.
8. **Сложная эксплуатация** – деплой/rollback/аварии приводят к потере данных, а локальная разработка не совпадает с продом.
